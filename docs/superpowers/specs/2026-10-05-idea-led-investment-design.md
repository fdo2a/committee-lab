# 아이디어 중심 투자 의사결정 흐름

작성일: 2026-10-05

사용자가 제안한 흐름은 산업·테마분석부와 마켓부의 아이디어·바스켓 컨셉 발굴 → 펀더멘탈부의 기업 분석 → 운용부의 종목 선정 → 리스크관리부 심사 → 투자 실행이다. 기술적 분석부는 별도 부서로 유지하며 운용부의 종목 선정과 진입 시점을 지원한다.

이 문서는 변경할 동작의 설계다. 현재 서버·화면·예약 실행은 아직 기존 방식이다.

## 목표와 역할

현재 네 조사 부서의 종목 추천 합집합을 편입 심사의 출발점으로 삼는 구조를, 투자 아이디어에서 출발하는 순차 검토로 바꾼다. 부서는 산업·테마분석, 마켓, 펀더멘탈, 기술적 분석, 운용, 리스크관리의 여섯 개를 유지한다. 투자 실행은 심사를 통과한 주문의 실행 단계이며 별도 조사 부서가 아니다.

산업·테마분석부는 기존 스크리닝부를 대체한다. 산업·제품·수요·산업 정책의 변화에서 투자 논리, 촉매, 확인할 사실, 논리 철회 조건과 후보군을 제안한다. 마켓부는 금리·환율·거시·시장 국면을 바탕으로 아이디어를 제안하거나 기존 아이디어의 시장 적합성을 평가한다. 두 부서 모두 바스켓 컨셉을 발굴할 수 있고, 한 부서의 제안을 다른 부서가 반대했다는 사실만으로 자동 탈락시키지 않는다. 반대 의견은 이후 판단에 남긴다.

펀더멘탈부는 아이디어 후보 기업의 실제 사업 연관성, 공시·IR, 수익·현금흐름·재무·밸류에이션을 분석한다. 기업별 통과·보류·반대와 근거를 기록하며 바스켓 비중을 정하지 않는다. 연간 숫자의 서버 검증은 질적 판단과 별도로 유지한다.

기술적 분석부는 기업 분석을 거친 후보의 추세·모멘텀·변동성·진입 시점을 검토한다. 외부 조사와 서버 가격 계산을 구분하며, 기술적 신호만으로 새 투자 아이디어나 편입 후보를 만들지 않는다.

운용부는 투자 논리와 기업·기술·시장 검토를 종합해 최종 종목, 예비종목, 비중, 방향, 전략, 손절·목표·기한을 결정한다. 점수 순위만으로 편입하지 않는다. 리스크관리부는 최종 편입안의 유닛·계좌·종목·업종·현금·증거금·노출·손절 손실을 심사하고 체결 직전에 다시 확인한다.

## 컨셉과 최종 바스켓 분리

기존 조사 저장·준비·실행 API와 서버 계좌를 재사용한다. 부서별 새로운 서비스나 모델 에이전트, 단계별 API는 추가하지 않는다. 입력 계약에 아이디어 목록을 추가하고, 기존 최종 유닛과 아이디어의 연결을 요구한다.

아이디어는 고유 ID, 이름, 제안 부서(산업·테마분석부 또는 마켓부 또는 둘 다), 지역, 분류, 투자 논리, 촉매, 관찰 조건, 철회 조건, 후보 종목과 선정 근거, 참조지수 근거, 조사 시점, 출처, 반대 의견을 갖는다. 컨셉 단계에서 최종 비중이나 주문 수량을 확정하지 않는다. 실제 관찰·가격 수집이 가능한 허용 종목만 후보에 넣는다.

기업 검토와 기술 검토는 아이디어 ID 및 종목에 연결한다. 운용부가 작성한 최종 `trendUnits`는 원본 아이디어 ID와 선정·제외 이유를 갖는다. 동일 아이디어는 복수 유닛으로 나눌 수 있지만, 기존의 동일 종목 신규 유닛 중복 배정 금지는 유지한다. 보유 유닛의 기존 조건을 바꾸기 위해 아이디어 ID를 재사용하지 않는다.

산업·마켓의 의견은 아이디어 발굴·적합성 판단, 펀더멘탈의 의견은 기업 검증, 기술의 의견은 가격·타이밍 지원으로 구분한다. 현재 종목별 `allow` 합집합은 새 주문의 독립 근거로 인정하지 않는다. 기업 검토나 기술 신호가 있어도 유효한 원본 아이디어가 없으면 신규 편입을 보류한다.

## 단계 완료 조건

아이디어 발굴 단계는 출처 있는 컨셉과 후보군이 준비돼야 한다. 기업 검토 단계는 해당 후보에 대해 사업 연관성·질적 판단·원문 출처가 기록돼야 한다. 기존처럼 모든 부서가 활성 종목 전부를 동일한 형식으로 조사하도록 요구하지 않는다. 기업·기술 검토의 필수 범위는 제안 아이디어의 후보군이며, 보유 종목의 별도 위험 감시는 계속한다.

운용부는 기업 검증을 통과한 종목만 최종 바스켓에 선정한다. 기술적 분석부의 외부 의견이 누락되면 지원 검토 미완료로 표시하고 신규 승인을 보류한다. 실제 진입에는 최신 서버 가격과 기존 검증 전략 신호도 필요하다. 제안 후보가 모두 탈락하거나 최종 유닛이 최소 구성 요건을 충족하지 못하면 현금을 유지하거나 컨셉을 재검토한다.

자료 누락은 누락한 단계·아이디어·종목·필드로 반환한다. 발굴 완료, 기업 검토 완료, 운용 편입안 작성, 위험 승인, 실제 체결을 서로 다른 상태로 표시한다. 하나의 완성된 조사 입력을 저장했다는 사실은 별도 모델들이 실제로 순차 실행됐다는 증거가 아니다.

## 유지할 운용 조건

새 부서 조사는 36시간 이내, 재무 수집은 24시간 이내, 연간 재무 기간은 550일 이내를 요구한다. 기존 흑자·매출 감소 15% 이내·PER 45배 이하와 비금융 영업현금흐름·차입금, 금융 ROE 조건을 유지한다. 거시 5항목과 참조지수 구성 확인은 120일 이내 기록을 요구한다.

최종 유닛 2~20개 구성종목, 예비 10개 이하, 유닛 예산 상한 40%, 첫 체결부터 1~3개월 기한, 손실 한도 절반에서 1회 절반 축소, 전체 손실·목표·기한·논리 훼손 시 청산 요청을 유지한다. 일부만 체결될 수 있고 축소 후 자동 재확대하지 않는다. 기존 실제 운용 유닛의 최초 손실 한도와 기한은 유지한다.

롱 종목 20%, 숏 종목 10%, 업종 40%, 총노출 100%, 숏 총노출 30%, 절대 순노출 80%, 신규 계획 손절 손실 0.8%, 합산 손절 손실 2%, 최대낙폭 10% 미만을 유지한다. 기존 추가 중형 10%·소형 또는 규모 미확인 5%·20일 평균 거래대금 1% 주문 한도와 승인 주문 한도 예약을 유지한다.

시장별 장전 판단·승인 → 승인 이후 실제 정규장 시가 모의 체결 → 마감 평가 흐름, 일시정지, revision 검사와 세션 중복 방지를 유지한다. 위험 청산은 신규 조사 불완전 때문에 중단하지 않는다. 가격 수집 실패 시 가격을 생성하거나 과거 시가로 대신 체결하지 않는다. 실계좌·유료 API·독립 모델 에이전트는 추가하지 않는다.

ETF 자산배분과 외부 시황 수집은 기존 별도 경로를 유지한다. 이번 변경은 주식 아이디어·기업 검토·최종 바스켓의 책임과 승인 근거에 한정한다.

## 호환성과 화면

기존 `screening` 식별자와 과거 부서 의견·거래·보고서는 읽을 수 있도록 보존한다. 새 입력의 산업·테마분석부는 새 표시명과 역할을 사용하고 기존 필드의 호환 해석을 명시한다. 과거 기록을 새 순차 검토 완료로 표시하지 않는다.

기존 최종 유닛 제안은 신규 아이디어 심사를 통과한 것으로 자동 변환하지 않는다. 새 주문에는 아이디어 연결과 단계별 검토가 필요하다. 기존 보유 유닛의 손절·목표·기한 감시는 유지하며, 변경 전에 승인된 미체결 진입은 새 조건으로 재심사하고 불충족 시 만료 처리한다. 계좌를 초기화하거나 같은 운용 세션을 다시 소비하지 않는다.

화면과 `/api/context`에서 컨셉 제안 부서, 원본 아이디어, 기업 검토, 기술 검토, 운용 선정 이유, 리스크 결과, 체결 상태를 연결해 표시한다. 산업·테마분석부 명칭과 여섯 부서의 역할을 일관되게 반영한다. 부서 요약은 조사 준비 상태와 최근 실행 결과의 기준 시점을 분리한다.

예약 실행의 조사 지침도 동일한 순서를 사용해야 한다. 서버가 요구하는 계약과 예약 작업의 제출 형식이 어긋나지 않도록 배포 시 함께 점검한다. 기존 예약의 시장·시간·활성 여부와 사이트 공개 범위는 보존한다.

## 구현 대상과 검증

기존 `web/committee.mjs`, `web/trend-units.mjs`, `web/engine.mjs`의 역할·아이디어 연결·후보 선정 조건을 수정한다. `worker/account.mjs`, `worker/research-readiness.mjs`, `worker/department-reviews.mjs`에서 새 조사 계약·단계별 준비 상태·보고를 반영한다. 기존 부서·유닛 화면, 자동 실행 지침, 관련 README를 같은 책임 구분으로 맞춘다. 필요한 필드는 기존 계좌 JSON에 저장하며 새로운 DB 테이블이나 의존성은 추가하지 않는다.

기존 테스트를 새 흐름에 맞춰 수정하고 다음 조건을 검증한다: 산업 또는 마켓의 출처 있는 컨셉에서 후보가 시작됨; 기업·기술 의견만으로는 새 후보를 편입하지 않음; 사업·숫자 검증 실패 기업을 선정하지 않음; 최종 유닛의 후보·아이디어 연결과 제외 이유 검증; 기술 검토 누락·조사 시점 초과·반대 의견 보존; 위험 한도와 체결 직전 재검사; 기존 보유 위험 청산 유지; 과거 입력·보고서 조회; 기존 승인 주문 재검사; 동일 세션 재시도 시 중복 주문·체결 없음.

## 검토 요청

위 역할·자료 흐름을 사용자가 검토한 후 구현 계획과 실제 코드 변경을 진행한다. 특히 기술적 분석부는 별도 부서로 유지하되 독립 아이디어 발굴 부서가 아니라 운용부 지원 부서라는 점을 반영한다.

> 2026-10-25 수정(사용자 요청 "매수 적격으로 통과하는 기준을 좀 더 널널하게"): PER 한도는 기본 60배, 매출 성장 15%·ROE 10%·영업현금흐름 양수이면 80배로 올렸다. 비금융 차입금/자기자본 한도는 4배이며, Yahoo가 차입금을 제공하지 않으면 그 항목만으로 탈락시키지 않는다(흑자·영업현금흐름 양수 조건은 그대로). 흑자·매출 감소 15% 이내·금융 ROE 5%·24시간 수집·위험 한도는 바꾸지 않았다.

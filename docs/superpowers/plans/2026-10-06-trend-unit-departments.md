# Trend Unit 부서 책임과 계량 선정 구현 계획

목표: 사용자 제공 운용 설명에 맞춰 기존 v5 아이디어→기업·기술 검증→바스켓→위험→모의체결 흐름을 보강한다. 기존 변경·계좌·청산·세션 계약을 보존한다.

결정: 별도 퀀트리서치부를 추가한다. 펀더멘탈부는 사업·공시·재무 검증, 퀀트부는 서버 계산과 후보 순위, 기술적 분석부는 진입 시점, 운용부는 최종 선정과 설명, 리스크부는 독립 한도 심사를 맡는다. 외부 AI의 새 부서별 입력이나 모델 호출은 요구하지 않는다.

- [x] `tests/quant-process.test.mjs`: 실제 후보의 순위·누락·신선도, 승인 이후 데이터 훼손, 컨셉 철회 청산, 유닛 간 상관·소요기간·성공률을 먼저 검사한다.
- [x] `web/quant-research.mjs`, `web/engine.mjs`: 기존 styleScore·historicalRisk를 재사용한다. 아이디어별 후보 최대30개를 순위화하고 최종·예비·제외 이유를 연결한다. 후보 전체 중 누락은 해당 행을 보류하며 선정 종목에만 신규 편입 차단을 적용한다. 승인·체결은 저장된 점수 대신 현재 자료를 재검사한다.
- [x] `web/trend-units.mjs`: 출처 있는 최신 컨셉 철회도 기존 유닛 청산으로 연결한다. 공통 관측일로 유닛 간 바스켓 수익률 상관을 계산하고 종료 유닛 단위의 비용 반영 성과·보유일·목표 도달일을 집계한다. 가중 종목 VaR를 바스켓 VaR로 부르지 않는다.
- [x] `worker/account.mjs`, `worker/department-reviews.mjs`, `worker/weekly-reports.mjs`: API 계약·보고·조회 시 재계산에 퀀트 책임·후보 순위·상관·KPI를 연결한다. v5 외부 조사 형식과 기존 데이터는 그대로 읽는다.
- [x] `web/app.mjs`, `web/trend-view.mjs`, `worker/mcp.mjs`: 일곱 부서, 후보 계량 근거, 유닛 위험·목표·성과를 기존 화면과 조회에 표시한다. 모든 제출 텍스트를 HTML escape한다.
- [x] 문서: 부서별 입력·출력·권한, 제안서와 구현의 차이, 단기채 대기 자산과 별도 채권 투자 구분, 예약 프롬프트 적용 여부를 정확히 기록한다.
- [x] 검증: `npm test`, `npm run check`, `npm run build`, `python3 -m unittest discover -s tests -p '*_test.py'`. 기존 청산과 계좌 기록 보존, 실제 시가 체결·중복 실행·보안 검사를 포함한다.

검토 초점: 후보가 다른 아이디어에 속할 때 순위를 재사용하지 않는다. 필요한 재무 팩터가 없거나 재무가24시간 이상 오래되면 편입하지 않는다. 날짜가 다른 시계열은 줄 번호로 맞추지 않는다. 부분 청산을 여러 아이디어의 승리·실패로 세지 않는다. 외부 컨셉 철회는 최신 조사일 때만 청산 사유로 사용한다.

검증 결과: Node159개, Python22개 통과. `npm run check`, `npm run build`, `git diff --check` 통과. 합성 자료만 사용하는 임시 로컬 화면에서 일곱 부서 탭·퀀트 순위표·유닛 목표·성과 표시와 콘솔 오류0건을 확인했다. 운영 DB·외부 예약은 변경하지 않았다.

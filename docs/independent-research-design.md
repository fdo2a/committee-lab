# 부서별 독립 발굴의 과거 설계 (v3, 2026-10-04)

2026-10-06부터 현재 흐름은 산업·테마분석부·마켓부의 컨셉/후보 발굴 → 펀더멘탈 검증 → 퀀트리서치부 서버 계산·기술 검증 → 운용 선정 → 리스크 심사 → 실행입니다. 아래는 당시 구조의 기록이며 신규 실행에는 적용하지 않습니다. 현재 계약은 [v5 설계](superpowers/specs/2026-10-05-idea-led-investment-design.md)와 `/api/context`를 따릅니다.

2026-10-04 사용자 승인: 각 부서가 종목을 리서치하고, 운용부와 리스크관리부가 최종 편입을 판단한다.

스크리닝·펀더멘탈·기술적 분석·마켓의 후보를 합집합으로 검토한다. 스크리닝의 점수나 반대 의견은 다른 부서 후보의 차단 조건이 아니다. 등록된 36개 종목군을 검토한다. 기존 계좌는 검증된 전체 실제 가격으로 준비할 때까지 24개 활성 종목을 유지한다. 후보 발굴과 편입 가능 여부를 구분하고, 사업·재무 자료 누락, 오래된 조사, 전략 조건 실패, 위험 한도 위반은 편입을 막는다.

`departmentResearch`에 부서별 최초 의견과 출처를 별도로 받는다. 의견 변경은 `revisedStance`와 `revisionReason`으로 기록한다. 기존 `screening` 입력은 탑다운·바텀업 근거를 분리해 호환하며, 기술적 분석의 규칙 계산과 외부 조사는 구분한다. 마켓의 외부 종목 추천이 없으면 관찰 의견으로 남긴다.

운용부는 제안 부서·반대 의견·전략·비중·청산 조건을 기록한다. 리스크관리부는 그 편입안을 별도로 심사하고 체결 직전 다시 검사한다. 승인만으로 체결하지 않고 기존의 새 가격 조건을 유지한다. 일정·계좌·위험 한도·사이트 공개 범위는 보존하며 파이프라인 변경으로 같은 슬롯을 재실행하지 않는다.

검증: 스크리닝 반대 시 펀더멘탈/기술/마켓 후보 검토, 최초/수정 의견 보존, 숫자 검증과 자료 신선도 차단, 승인·체결 전 재검사, 기존 롱·숏 및 중복 실행 회귀 테스트. 비공개 서버와 공개 조회 화면에 같은 흐름을 표시한다.

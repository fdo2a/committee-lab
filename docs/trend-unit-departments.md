# Trend Unit 운용: 부서 책임과 프로젝트 점검

2026-10-06. 사용자가 제공한 전략 설명을 기준으로 `committee-lab`의 조사 계약, 재무·가격 수집, 계좌, 유닛 청산, ETF 운용, 화면, MCP, 주간 보고서를 점검했다. 정본은 `committee-lab`이며 `committee-public`은 이전 주소 이동용이다. 제안서의 과거 종목·시장 전망·수익률을 현재 매수 신호로 사용하지 않는다.

## 2026-10-21 선정 부서 전환: 살지 말지가 아니라 어떤 걸 살지

퀀트리서치부·기술적분석부·리스크관리부는 매수 거부권을 갖지 않고 어떤 후보를 살지 정하는 선정 순위에 참여한다. 서버는 `selectionScore`로 퀀트 점수(4개 팩터 미확인이면0)와 기술 점수를 50%씩 더하고, 국면에 맞는 검증 전략 진입 신호가 있으면10점을 가산한다. 이 가중치는 유닛 성과로 보정할 초기값이다. 상위 후보부터 편입안을 만들고, 리스크관리부는 앞선 편입안의 현금·노출 예약을 반영해 `fitRiskQty`로 한도 안 최대 수량을 배정한다. 한도를 넘는 후보는 거절하지 않고 수량을 줄인다. 1주도 들어가지 않을 때만 `보류`다.

검증 전략 진입 신호가 없어도 편입안·승인은 가능하며 전략은 `미검증`으로 기록된다. 승인·체결은 서버 재무 숫자·30일 이내 수집(연간 재무는 주 1회 재조회, 수집 경과 자체는 보류 사유가 아님), 사업·유닛·후보 근거와 계좌 하드 한도(현금, 종목20%/숏10%, 업종40%, 총노출100%, 숏30%, 순노출80%, 계획 손실0.8%, 합산 손절5%, 최대낙폭10%, 규모·유동성)를 계속 요구한다. 손절은 기존 2×ATR 또는4% 중 큰 값이다.

같은 날 사용자 요청으로 매매를 더 적극적으로 바꿨다. 합산 손절 손실 한도를 2%에서5%로 올려 동시 보유 종목 수를 늘리고, 롱 신규 계획의 기본 크기를 비중12%→15%, 계좌 위험0.6%→0.8%로 키웠다. 숏 기본 크기(8%, 0.4%)와 다른 하드 한도는 그대로다. 이 절은 이전 문서의 합산 손절2% 기준을 대체한다.

## 결정: 퀀트리서치부를 별도로 둔다

펀더멘탈부에 계량 선정까지 맡기면 사업 판단과 점수 계산의 책임이 섞인다. 기술적 분석부에 합치면 가격 모멘텀과 진입 시점에 역할이 치우친다. 별도 퀀트리서치부가 같은 후보의 숫자를 동일 규칙으로 계산하고, 운용부가 그 결과와 기업 검토를 함께 판단하는 구조를 선택했다.

이는 일곱 번째 **논리적 부서**다. 새 AI 모델·유료 API·외부 조사 행을 추가하지 않는다. 기존 서버 재무·가격과 `styleScore`·`historicalRisk`를 재사용한다. 기업 검증을 통과했다고 높은 점수를 보장하지 않으며, 높은 점수도 기업 검증이나 투자 승인을 대신하지 않는다.

## 부서별 입력·산출물·판단 권한

### 마켓부

성장·물가·정책·유동성·선행지표와 금리·환율·크레딧·원자재·포지셔닝을 검토해 향후 1~3개월 시장 국면을 판단한다. 산출물은 지역별 `macroScorecard`, `marketReview`, 거시 아이디어와 반대 근거다. 강세·횡보·단기 약세·장기 약세의 판단과 현금 대기 논리를 설명해야 한다. 가격 수집 종목의 상승 비율은 참고치이며 글로벌 국면 판단을 대체하지 않는다. 관측하지 않은 크레딧·실질금리·포지셔닝은 미확인으로 남긴다.

### 산업·테마분석부 (`screening`)

마켓부의 환경 판단을 산업 수요·정책·설비투자·실적 촉매와 연결한다. `investmentIdeas`에 투자 논리, 촉매, 관찰 조건, 철회 조건, 참조지수와 후보별 이유를 기록한다. 후보는20~60개를 목표로 최대100개까지 조사한다. 직접 수혜·간접 수혜·공급망·장비·소재까지 넓게 비교하고 기업별 컨셉 연결 이유를 남긴다. 지수 전체와 실제 조사한 부분집합을 구분하고 구성 확인일·출처를 남긴다. 이 부서는 후보를 발굴하며 사업 통과나 최종 투자 승인을 하지 않는다.

### 펀더멘탈부

발굴 후보가 해당 아이디어와 실제로 연결되는지 사업·고객·제품·경쟁·공시·현금흐름·가치평가를 검증한다. 산출물은 `(ideaId,symbol)`별 출처 있는 `departmentResearch.fundamental`과 사업 통과·반대 근거다. 서버는 수집한 재무의 동일 기간·통화·필수 계정과 기존 수치 기준을 별도로 검사한다. 연간 매출성장은 EPS 전망 수정이나 분기 이익모멘텀과 다른 지표다. 다른 아이디어의 같은 기업 검토로 통과를 대체할 수 없다.

### 퀀트리서치부 (`quant`, 서버 계산)

각 아이디어의 후보를 대상으로 가치(PER), 퀄리티(ROE), 성장(연간 매출증가), 방향별 가격모멘텀을 각각0~100점으로 계산해25%씩 동등가중한다. 기존 단순 점수식을 재사용한다. 숏 헤지 후보의 가격모멘텀은 하락 방향으로 계산한다. 후보군 안에서 점수순으로 정렬하며 동점은 종목 기호순으로 처리한다. 이는 수익률 예측이나 공식 MSCI 팩터 점수가 아니다.

산출물은 `analysis.quantResearch`: 아이디어 ID·계산 시각·후보별 팩터·점수·순위·재무 출처/기간·위험 참고치·선정/예비/제외와 운용 이유다. 4개 팩터, 서버 숫자 통과, 수집 30일 이내이 모두 확인돼야 순위를 부여한다. 누락 후보는 점수를 있는 것만 평균하지 않고 순위 없이 순위 후보 뒤로 보낸다.

규모·배당·EPS 전망 수정치는 현재 미수집이므로 `null`로 표시한다. 후보가 적으면 순위의 구별력도 작다. 실제 재무·가격 없이 LLM이 만든 점수는 사용하지 않는다. 퀀트부는 매수 여부(거부권)를 결정하지 않고 어떤 후보를 먼저 살지 순서를 정한다. 운용부 편입안은 퀀트 순위 순으로 만들어 현금·위험 한도가 남는 상위 후보부터 편입된다. 매수 여부는 펀더멘탈·서버 재무 검증, 유닛·전략 검증, 리스크 한도가 결정한다. 퀀트부는 원본 테마·사업 통과·최종 비중을 결정하지 않는다.

### 기술적 분석부

같은 후보의 추세·돌파·눌림·모멘텀·변동성과 진입 시점을 검토한다. 산출물은 `(ideaId,symbol)`별 `departmentResearch.technical`과 허용·관찰·반대 근거다. 퀀트부가 종목 간 비교를 맡고 기술부는 해당 시점의 실행 적합성을 맡는다. 외부 의견과 서버 기술 점수는 선정 순위에 반영되고, 검증 전략의 진입 신호는 가산점이며 필수 조건이 아니다.

### 운용부

거시·산업 논리, 기업 검증, 계량 순위, 기술 의견과 반대 근거를 종합해 실행할 유닛을 선택한다. 산출물은 원본 `ideaId`에 연결된 `trendUnits`, 구성·비중, 예비·제외 이유, 목표수익·손실 한도·1~3개월 기한과 배분·위험 근거다. 각 종목 계획에 계량 순위·점수·선정 이유·계산 시각을 남긴다. 최고 점수 종목을 무조건 편입하지 않으며 순위와 다른 선택도 이유를 기록한다. 실행할 아이디어가 없으면 출처 있는 관찰 결정을 남기고 현금·허용 대기 자산을 유지한다.

### 리스크관리부

선정 순위대로 현금·예약 주문·증거금·종목·업종·총/순노출·손실 한도 안의 수량을 배정하고 넘치면 축소한다. 체결 직전에는 같은 한도를 하드 상한으로 다시 검사한다. 종목 위험뿐 아니라 유닛 간 상관·중복과 미확인 쌍을 확인한다. 상관0.8 이상은 집중 경고의 참고 기준이며 새로운 일률적 매매 금지 규칙은 아니다. 기존 손실 한도 절반에서1회 절반 축소, 전체 한도·목표·기한·최신 논리 철회에서 청산을 예약한다. 휴장·장중 관측 한계 때문에 실제 청산은 승인 이후 확인되는 정규장 가격을 기다린다. 손절선이 실제 손실의 상한을 보장하지 않는다.

## 제안서 대비 점검과 반영

**Top-down → 참조지수 → 후보 검증 → 계량 압축 → 운용 선정.** 기존 v5 원본 컨셉·후보·기업/기술 검토의 연결은 유지하고 계량 단계의 주체·순위·근거를 보강했다. 외부 조사 형식은 v5와 호환된다. `/api/research-check`의 `readyUnitIds`는 조사 계약 준비 여부이고 실제 재무·계량·진입·위험·체결 통과를 뜻하지 않는다.

**바스켓 규모.** 제안서의5~20개는 `quantMethod.preferredMembers`에 명시했다. 기존 실제 조사 범위가 작은 경우를 위해 서버 허용2~20개는 유지한다. 후보를 억지로5개 채우지 않는다. 예비는10개 이하, 유닛 비중은40% 상한이며20% 하한을 강제하지 않는다. 계좌·종목·업종 손실 한도가 실제 편입을 더 줄일 수 있고 일부만 체결될 수 있다.

**유닛 교체와 위험 청산.** 첫 체결 시 기한과 손실 조건을 고정한다. 최신 출처 있는 원본 컨셉의 `action:withdraw`도 보유 유닛 청산으로 연결했다. 기존에는 별도 유닛 `action:exit`가 있어야 논리 훼손 청산이 연결됐다. 축소 후 회복은 재심사·새 ID로 처리하며 같은 ID의 손실 한도·기한 확대는 금지한다. 제안서의 자동 재확대·일간 목표 조정은 그대로 복제하지 않는다.

**상관과 숨은 집중.** 실제 수집 일봉의 `time`을 시장별 시간대의 거래일로 연결해 기존 유닛 내부 상관에도 사용한다. `portfolioUnitRisk`는 유닛별 고정 구성비 수익률의 공통 관측구간60개 이상으로 유닛 간 상관과 종목 중복을 계산한다. 날짜·기간이 맞지 않으면 미확인으로 표시한다. 역사적 FX·실제 리밸런싱·팩터 회귀를 포함하지 않으므로 AI capex나 금리 민감도를 분해한 완성된 팩터 모델은 아니다.

**VaR와 목표·손절.** 과거 중첩60거래일 손실 분위수와 변동성은 위험 근거로 제공한다. 목표·손실률은 운용부가 사전 설정하며 제안서의 예시 숫자를 고정하지 않는다. 종목 위험값의 가중평균을 바스켓 VaR로 표현하지 않는다. 현재 목표를 VaR로 자동 최적화하는 알고리즘이나 미래 손실 보장은 구현하지 않는다.

**유닛 단위 복기.** 종료 유닛1개를1건으로 세며 부분 청산·구성 종목 청산을 여러 성공/실패로 세지 않는다. 수익 성공률과 목표 도달률을 분리하고 평균 성공 수익·실패 손실·보유일·목표 도달 관측일까지의 날짜·비용 반영 실현손익을 제공한다. 미완료 유닛은 성공률에서 제외하고 표본이 없으면0% 대신 미확인으로 표시한다. 주간 보고서는 해당 주에 종료된 유닛만 별도로 집계한다.

**현금과 채권.** 현금 대기는 유효한 운용 결정이다. 현재 시스템에는 한국·미국·일본 단기채 ETF 대기 운용과 별도 근거를 요구하는 중장기 국채·회사채 운용이 이미 있다. 중장기·신용채는 제안서의 듀레이션1년 미만 대기 자산과 같은 것으로 설명하지 않는다. 주식 주문·숏 증거금이 우선이고, 채권 매도는 실제 후속 시가에서 현금으로 돌아온다. 국면 변화만으로 가짜 이자·배당·환율 수익을 만들지 않는다.

## 적용 범위와 운영 상태

2026-10-08 적극적 진입 조정: v5 가격 전략 검증을 전체 관찰종목에서 해당 Trend Unit의 최종 구성종목으로 한정했다. 바스켓 n종목의 훈련 청산은 최소 `max(3,n)`건, 분리 검증 청산은 최소 `max(2,ceil(n/2))`건이다. 두 구간 평균 수익 양수·검증 개별 최대낙폭15% 이하, 현재 시장·종목 진입 신호를 요구한다. 훈련은 앞 `max(220,floor(거래일 수×70%))` 거래일이다. 다른 종목의 거래 부족 때문에 검토 완료 테마를 보류하던 병목을 줄이고, 계획 생성과 승인에 같은 바스켓 검증을 적용한다. 전체 관찰종목 연구는 비교용으로 구분한다.

기업·계량·자료 신선도와 기존 위험 한도는 유지한다. 계획 손실0.8%, 합산 손절 손실2%, 종목20%/숏10%, 업종40%, 총노출100%, 절대 순노출80%, 숏 총노출30%, 최대낙폭10%, 유닛40%, 중형10%·소형/규모 미확인5%와 거래대금1% 한도를 확대하지 않는다. 훈련·검증 최소 거래 수는 작은 바스켓의 구성에 맞춰 줄어들므로 통계적 신뢰가 높아졌다는 의미가 아니다. 같은 전략의 연속 손실 중단·규모 축소는 계속 적용한다. 계획과 주간 보고서에 실제 바스켓 검증 종목·훈련/검증 거래 수를 기록한다.

화면의 부서 탭·위원회·Trend Unit 패널, `/api/context`, 실행 부서 기록·요약, 주간 보고서 자료, MCP 조회에 연결했다. MCP의 이전 검토 제외 조회는 새 계량 선정 이유도 제외한다. 외부 AI의 조사 입력에 새 `departmentResearch.quant`를 요구하지 않는다. 기업·기술 원문 검토, 기존 재무·전략·위험·체결·중복 방지·접근 통제는 유지한다.

이 변경은 로컬 코드와 빌드 결과에 반영한다. 기존 외부 예약을 편집하거나 배포됐다고 주장하지 않는다. 실제 적용에는 정본 Site의 이 빌드 배포가 필요하다. 기존 예약이 실행 때 읽는 `/api/context`에 새 퀀트 단계가 포함되므로 배포 후 계약을 따라 사용할 수 있다. 예약 문구 보완안은 `scheduled-research-v5.md`에 따로 기록한다.

MSCI 공식 방법론은 각 지수별 문서로 제공된다. 이 구현의 단순 점수와 구분한다. [MSCI 공식 방법론 목록](https://www.msci.com/indexes/index-resources/index-methodology).

## 컨셉 조사와 편입 압축

발굴·원문 조사 후보(목표20~60개·최대100개), 계량 압축 후보(상위30개), 최종 편입(권장5~20개·허용2~20개), 예비(최대10개)를 구분한다. 전체 후보를 분석 대상으로 보존하고 미분석·미선정은 관찰로 둔다. 후보 발굴에는 등록 여부·컨셉 연결·지역·참조 Universe 근거가 필요하며 가격 수집 전에도 가능하다. 특정 지수 전체와 자체 테마 Universe를 혼동하지 않는다.

펀더멘탈부는 직접/간접 사업 연결, 실제 매출·고객·공급망, 촉매, 밸류에이션 부담과 반대 근거를 후보별 원문으로 검토한다. 퀀트부는 자료가 갖춰진 전체 후보를 비교해 상위30개를 표시하며 낮은 순위와 미확인 후보도 남긴다. 기술부는 실제 가격 자료를 확보한 후보부터 순차 검토한다. 운용부는 최종·예비·명시적 제외만 결정하고 다른 후보를 억지로 분류하지 않는다.

`researchReadiness.coverage`는 컨셉별 후보수·기업/기술 검토 완료수·가격 수집수·분석 대기 종목·최종 선정수를 제공한다. 같은 컨셉의 미선정 후보 검토 누락은 완성된 유닛의 심사를 막지 않지만 전체 조사 상태는 미완료로 유지한다. 원본 컨셉·참조 Universe·지역 매크로와 최종 편입 종목의 검토·실제 가격 누락은 계속 편입을 막는다. 부분 저장은 기존 검토를 포함한 전체 자료 교체이며 유효기간만 연장하는 갱신은 금지한다.

체결 정책 v4: 장전 리서치·승인 후 개장에 주식·ETF 매수와 신규 숏을 해당 거래일 시가로 편입하고, 마감에는 평가·위험 점검을 수행한다. 매수·숏 진입은 기준가 대비 3% 변동으로 보류하지 않으며 체결 직전 계좌 하드 한도(현금·노출·손실)만 재검사한다. ETF 매수 수량은 가용 예산에 맞춰 축소하고 ETF 매도의 3% 점검은 유지한다. 시가 미수집 시 `awaitingOpen`으로 같은 개장 단계에서 재시도한다. 매도·상환은 승인 이후 시가를 사용하며 승인 이전 시가로 소급 체결하지 않는다. 기존 수수료·슬리피지와 승인 단계의 자료·위험 심사는 유지한다.

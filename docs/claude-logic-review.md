# Claude 논리 검토 운영

Claude Code는 논리 심사만 한다. 전제의 모순, 근거 없는 인과관계, 근거보다 강한 결론, 반대 근거·철회 조건 누락, 요구사항과 코드의 불일치를 지적한다. 가격·재무·정규장·위험·회계 검사는 기존 서버와 테스트가 담당한다. 승인 문장은 그 검사를 대신하지 않는다.

이 프로젝트의 기본 모델과 로컬·클라우드 투자 검토, 코드·보안 최종 검토는 모두 Sonnet 5.5 medium이다. `.claude/settings.json`은 프로젝트 기본값을 지정하며, 자동 검토는 `--model`과 `--effort medium`을 명시한다. 클라우드는 설정 파일을 읽지 않아도 같은 모델과 effort를 명시한다. 모델 버전은 자동 별칭 변경을 피하도록 고정한다. 구독 사용 한도나 인증 실패 시 유료 API로 전환하지 않고 기존 보류 규칙을 유지한다.

## 코드

관련 수정은 한 묶음으로 마무리한 뒤 배포 전 최종 검토를 한 번 요청한다. 중간 수정·설정 문법 확인·조회·보고서 작성마다 별도 Claude 심사를 호출하지 않는다. 전체 로컬 검사를 통과한 현재 소스와 일치하는 등록키 서명의 15분 이내 승인이 있으면 새 모델 호출 없이 그 승인으로 빌드한다. 소스 변경·만료·서명 불일치는 새 승인이 필요하다. 반려 후 보완 결과가 같거나 코드 소스 해시가 같으면 같은 근거를 반복 심사하지 않고 보류한다.

로컬 공개키 환경변수를 설정한 뒤 프로젝트에서 `npm run review:code`를 실행한다. 현재 Mac의 등록 공개키는 `~/.codex/committee-review/public-key.json`에 있으며 개인키와 분리된 공개 자료다. 전체 Node/Python 테스트와 구문 검사를 먼저 실행하고 `sourceFiles()`가 해시하는 전체 파일을 Claude에게 보낸다. 마지막 승인 기준점이 없으므로 커밋된 변경·카탈로그·`worker/mcp.mjs`도 생략하지 않는다. 전체 자료가 도구 한도를 넘으면 승인하지 않고 보류한다. 반려되면 Codex가 해당 논리를 수정하고 테스트·Claude 심사를 반복한다. 코드 심사는 최대5회/총45분이며 실패하면 산출물 갱신·배포를 중단한다. 이 명령은 통과한 소스로 빌드까지 완료한다. 이후 `npm run build`도 최신 해시와 유효한 승인이 있어야 실행된다.

논리 검토 기록은 로컬 `.review/code-round-N.json`, 승인 증명은 `.review/code-approval.json`에 저장하며 배포하지 않는다. 승인은15분 유효하고 소스 변경 시 무효다. 서버와 로컬 빌드 환경의 `CLAUDE_REVIEW_PUBLIC_KEY`에는 운영자가 별도로 등록한 동일한 공개 RSA JWK를 사용한다. 빌드는 승인 파일 안의 `publicKey`를 신뢰하지 않으며 등록된 키가 없거나 서명이 다르면 중단한다. `.env.example`은 설정 안내이며 `.env.local`을 자동으로 읽지 않으므로 로컬 명령에도 이 공개키 환경변수를 설정해야 한다. `.review/public-key.json`은 등록을 위한 공개키 출력일 뿐 빌드의 신뢰 근거가 아니다.

기존 서명기의 기본 개인키 위치는 `~/.codex/committee-review/private.pem`이며 최초 실행은0600으로 생성한다. 다른 위치는 `COMMITTEE_REVIEW_KEY`로 프로젝트 밖에 지정한다. 이 파일 방식은 모델 파일 접근을 격리하지 않는다. 같은 OS 사용자로 실행되는 Codex의 read-only/workspace-write 샌드박스는 키를 읽을 수 있고0600과 환경변수 필터도 이를 막지 못한다. 개인키나 서비스 인증을 모델 입력·환경변수로 전달하지 않는 것과 모델이 파일을 읽을 수 없는 것은 별개다. 현재 방식의 운영 경계는 해당 OS 사용자와 모델 하위 프로세스를 신뢰하는 것이며, 신뢰할 수 없는 조사 내용에 의한 프롬프트 주입까지 차단한다고 주장할 수 없다. 파일 접근 격리가 필요하면 별도 OS 계정의 서명기로 분리해야 한다. 이번 수정은 키의 열람·이동·교체를 수행하지 않는다. 키 교체 시 서버와 로컬의 등록 공개키도 함께 갱신한다.

## 예약 운용

개장·마감에서 현재 서버 문맥으로 비위험 승인 대기 주문이 없다고 확인되는 주식·ETF 요청은 위험 전용 제출까지만 처리하며 `reviewNotNeeded`로 모델 호출을 생략한다. 오래된 서버 문맥이나 판단 불가한 주문 상태는 생략하지 않는다. 장전·신규 판단·매수/숏/비위험 청산 대기 주문은 기존 심사를 유지한다. 생략은 승인을 부여하지 않으므로 신규 체결 게이트는 그대로 유지된다.

같은 수집 후 30분 창에서 `claudeUsageLimit` 또는 `claudeAuthenticationUnavailable`을 확인하면 다른 범위의 후속 모델 호출도 보류한다. 위험 전용 제출은 계속한다. 새 창으로 갱신해 오류나 원래 자료 기한을 우회하지 않는다. OAuth 등록 자체는 심사를 실행하지 않으며, 최초 활성화 전에 필요한 읽기 전용 구독·서명 진단만 명시적으로 수행한다.

2026-10-10 승인된 신규 운용 경로는 [Claude 구독+JEV 클라우드 설계](superpowers/specs/2026-10-10-cloud-investment-design.md)다. updater는 `logicReview.cloudConfigured:true`이면 비공개 GitHub 구독 검토 대기열을 사용한다. 실제 인증·읽기 전용 증명 검증 전에는 클라우드 활성화를 끄고 Mac 예약도 PAUSED로 유지한다. 아래 Mac 운용 절차는 클라우드 활성화 이전 및 로컬 호환 경로의 기록이며 현재 Mac 예약을 재개하라는 지침이 아니다. [클라우드 운영·재시도 계약](cloud-review-setup.md)을 우선한다.

저장된 이전 Mac 예약이 `reviewWindow` 없이 `reviewStartedAt`·`reviewDeadline`을 전달하면 updater는 그 값을 기존 창으로 사용하며 수집 뒤 새30분을 열지 않는다. 두 값 중 하나가 없거나 유효하지 않으면 신규 검토를 보류하고 위험 전용 처리는 유지한다. [저장 관찰 기록](claude-schedule-verification.md)은 당시 증거로 보존한다. Mac 예약 활성화 전에는 두 예약 지시문을 아래 `reviewWindow` 계약으로 갱신하고 재조회로 확인해야 한다. 시간 창을 확인할 수 없는 재호출은 `reviewWindow:null`을 전달하여 보류하며 시각 필드를 생략해 신규 실행처럼 호출하지 않는다.

Mac 호환 경로의 서명에는 cloudJobId가 없어 서버에 reviewStartedAt이 전달되지 않는다. 장전에도 fetchedAt부터30분 신선도 검사가 적용되므로 수집·ETF 심사가 길어지면 알린 검토창 안에서도 priceEvidenceStale로 보류될 수 있다. 수집 시간을 검토30분에서 제외한다는 요구를 이 경로가 완전히 충족하지 못하는 한계이며, 현재 Mac 예약은 PAUSED로 유지한다.

Mac에서 검토하는 실행은 해당 프로젝트의 조사 지침으로 판단 JSON을 준비한다. Sites `get_site`로 매번 기존 Site와 소유자 전용 접근을 확인하고 서비스 인증을 메모리에만 얻는다. 기존 로컬 `web/run_autonomy.py`에 JSON stdin으로 `site_url,token,market,phase,research,allocationDecision`을 전달한다. 최초 실행에는 검토 시작 시각을 미리 정하지 않는다. updater가 가격·재무·ETF 자료 수집을 끝낸 뒤 `reviewWindow:{reviewStartedAt,reviewDeadline}`을 만들며 그때부터 최대30분이다. 동일 실행의409 재호출에는 정상 결과 또는 오류 JSON에 반환된 `reviewWindow`를 그대로 stdin에 넣는다. 검토를 시작한 실행에서 window를 확인할 수 없으면 새 시간으로 재시도하지 않고 보류한다. 잘못되거나 만료된 window는 신규 검토만 보류하며 위험 전용 처리는 유지한다. 최신 코드와 가격·재무 자료를 사용하며 서버 `/api/session`으로 단계·휴장 여부를 확인한다. [예약 운영 경계](scheduled-research-v5.md#claude-검토-전환의-예약-운영-경계)에 따라 신규 투자 예약은 Mac 하나로 제한하고 기존 클라우드는 위험 전용으로 유지한다. Mac 예약은 승인된 배포와 서버 게이트 확인 뒤 활성화한다.

Updater는 기존 보유 주식의 위험 처리를 ETF 모델 심사보다 먼저 수행하고 ETF도 자체 모델 심사 전에 위험 점검을 저장한다. ETF 수집·409·저장 확인 실패는 별도로 보고하고 최신 context를 다시 읽어 주식 위험 점검을 계속한다. 이후 최신 `/api/context`와 계좌 revision으로 Claude 심사를 실행한다. Codex는 반려된 research/decision만 보완하며 수집 가격·재무·시각·시장·단계·revision은 변경할 수 없다. 서명 전에 Mac 체크아웃의 `sourceDigest()`가 서버 `codeDigest`와 같은지 확인하고 심사 뒤에도 로컬 소스 변경을 확인한다. 불일치하면 보류한다. 승인 결과는 정확한 요청 본문·API 경로·동일한 로컬/서버 코드 버전과 함께 서명한다. 서버는 변조·만료·다른 버전·경로·계좌에 대한 증명을 받지 않는다. 세션·4시간 호환 모드 모두 최신 계좌 revision을 요구한다.409이면 해당 증명을 재사용하지 않는다. 실행 주체가 최신 context로 다시 호출할 때도 최초 실행의 `reviewStartedAt`·`reviewDeadline`을 유지한다. 이미 저장한 위험 점검·청산은 보존되며 충돌한 요청은 저장하지 않는다.

주식의 신규 buy/short 승인과 체결, ETF 신규 매수·임의 리밸런싱·새 판단은 승인 대기한다. 기존 손절·목표·유닛 손실/기한·증거금 부족·퇴출 ETF 청산은 검토 실패 시에도 기존 실제 정규장 규칙으로 진행한다. 미승인 새 투자논리의 청산 지시는 위험 청산으로 취급하지 않는다. 보류한 단계는 완료 처리하지 않아 같은 단계에서 재시도할 수 있다. 다른 아이디어의 조사 대기는 이미 준비된 바스켓을 막지 않는 기존 기준을 유지한다.

클라우드는 검토 창 하나에 최대5회이며 ETF·주식·반려 보완·409 revision 충돌 재심사가 이5회를 공유한다. 동일 초기 요청의 중복 조회는 회차를 늘리지 않는다. 중지된 Mac 호환 경로의 기존 reviewLoop는 범위별5회이며 클라우드 예약 한도를 뜻하지 않는다. 두 경로 모두 ETF·주식 심사와409 재호출은 수집 완료 후 최초 검토 시작부터 총30분을 공유한다. 수집에는 이30분 제한을 적용하지 않는다. 장전은 실제 개장, 개장은 실제 마감, 마감은 해당 거래일 종료 중 먼저 도달하는 한도로 더 제한한다. 만료하면 신규 심사·승인 제출은 보류하지만 위험 전용 제출은 유지한다. 인증·구독 한도·자료·도구 실패는 `logicReviewHeld`로 보류한다. 유료 API나 크레딧 구매로 전환하지 않는다. Claude가 판단을 보완해도 과거 가격이나 종가로 새 승인을 소급하지 않는다.

`/api/research`·`/api/universe`의 저장 조사는 심사 증명이 없으므로 개장·마감의 새 논리 청산에 쓰지 않는다. screening exit·유닛 exit·아이디어 withdraw는 현재 승인 요청 본문에 포함되어 정제에 성공한 조사에서만 청산 지시를 생성한다. 장전 승인된 투자논리 청산도 개장·마감의 위험 전용 실행에서는 체결하지 않는다. 체결에는 별도의 유효한 서명 승인 실행과 승인 이후의 실제 정규장 시가가 필요하다. 수동 청산 요청은 현재 검토된 조사에서 생성한 주문이 아니므로 서명된 장전 실행만으로 자동 승인하지 않는다. 실제 손절·증거금 부족·유닛 손실/목표/기한 조건이 발생하면 대기·승인·보류 상태의 비위험 청산 주문(배포 전 주문 포함)을 취소하고 위험 사유가 있는 새 주문을 생성한다. 새 위험 주문도 조건 확인 이후의 정규장 시가 체결 규칙을 유지한다.

Mac이 꺼져 있거나 Codex 앱이 종료된 시간에는 로컬 검토가 실행되지 않는다. 서버는 자동으로 신규 투자를 허용하지 않는다. 클라우드 updater는 `collect_prices.py`, `collect_fundamentals.py`, `run_autonomy.py`, `logic_review.py`, `index-catalog.mjs`, `etf-catalog.mjs`를 같은 임시 디렉터리에 받아야 하며 검토 재호출에는 위 reviewWindow를 유지해야 한다. Mac 검토 스크립트가 없는 환경은 위험 전용 요청을 먼저 제출하고 `macReviewerRequired`로 신규 활동을 보류한다. 두 기존 클라우드 예약의 저장 후 재조회 증거는 [예약 저장 증거](claude-schedule-verification.md)에 있다. 이 확인이 배포 선행 조건이며, 승인된 소스의 배포 확인 뒤 Mac 예약을 활성화한다.

`worker/mcp.mjs`는 전체 코드 검토 자료에 포함한다. 조회·검증 도구와 별도 JEV 평가 기록 도구가 있다. JEV 도구는 평가 기록을 저장할 수 있으나 후보·비중·주문 승인·체결을 변경하지 않는다. 이 별도 기능의 유료 호출은 명시적 opt-in이며 Claude 검토의 유료 API 대체 경로로 사용하지 않는다. 계좌 revision·현금·주문·체결 보존 여부는 `tests/mcp.test.mjs`로 확인한다.

승인 대기 중인 주식 buy/short 주문이 있으면 증명 없는 `/api/research`·`/api/universe` 준비 요청은 상태를 바꾸기 전에409로 거부한다. 승인된 진입의 근거를 바꾸려면 새 조사 전체를 서명된 운용 요청에 포함하여 다시 심사받아야 한다.

클라우드 장전의 원본 가격·ETF 증거는 reviewStartedAt 시점에30분 이내인 경우에만 서버가 고정한 검토 기한까지 사용한다. 수집 시간이 길어 시작 전에 가격이 이미 만료되면 priceEvidenceStale로 보류하며 검토로 유효시간을 갱신하지 않는다. 실제 체결이 가능한 개장·마감과 미승인 위험 제출은 기존 fetchedAt30분 기준으로 새 가격을 검사한다. 최종409·400은 jobId·scope·reason을 가진 보류로 반환하며 reviewJobId로 같은 창에서 원본 증거와 최신 revision을 재심사한다. 원본 가격의 위험 전용 재제출과 실패한 증명의 재사용은 하지 않는다. 시장 없는4시간 호환 모드는 클라우드 검토에서 sessionPhaseRequired로 보류한다.

클라우드 개장·마감의 공유 reviewDeadline은 검토 시작+30분, 시장 단계 종료, 주식 fetchedAt+30분과 모든 ETF fetchedAt+30분 중 가장 이른 시각이다. 큐도 제출 범위의 가격 기한보다 긴 창을 거절한다. 이 경계와 장전 증거 사용 방식은 승인 요구 원문에 추가하지 않고 [별도 구현 결정](cloud-review-setup.md#implementation-decisions-and-approval-boundary)에 기록한다.

## 2026-10-08 재개 상태 (당시 기록, 현재 상태는 reports/claude-review-2026-10-09.md 참고)

전체 Node207개·Python34개·구문 검사는 통과했다. 실제 Claude CLI는 세션 사용 한도로 거절했으며 오늘22:40 Asia/Seoul에 재설정된다. 최종 Claude 승인과 배포는 완료되지 않았다. Site는 여전히 버전29이고 `/api/context.logicReview`는 없다. 두 Mac 예약은 PAUSED다. 기존 클라우드 예약은 위험 전용으로 저장했지만 새 updater·서버 게이트가 배포되기 전에는 이 전환 경로를 실행할 수 없다.

재개 시 이 체크아웃의 최신 소스 전체로 `review:code`를 다시 실행한다. 등록 공개키는 `~/.codex/committee-review/public-key.json`에서 환경변수로 읽고 개인키·서비스 인증은 모델에 넘기지 않는다. 반려 시 동일 제어기가 보완·재검토하며 코드 심사5회/45분 실패는 계속 보류한다. 승인된 해시가 현재 소스 및 빌드와 같은지 확인하고 Sites의 기존 소스 체크아웃·비공개 배포 절차로 반영한다. `/api/context.logicReview`의 required/configured와 codeDigest를 확인하고, 두 Mac 예약 지시문을 `reviewWindow` 계약으로 갱신한 뒤 재조회로 확인한 경우에만 committee-lab-mac 및 committee-lab-mac-2를 ACTIVE로 갱신한다. 기존 일시 중지 예약은 유지하고 실제 예약 실행 전 계좌 변경 시험은 하지 않는다.

배포 전 승인된 위험 청산은 readAccount에서 기록된 손절·목표·증거금·유닛 손실/목표/기한 사유와 퇴출 ETF 주문만 위험 플래그로 이관한다. 이미 명시된 riskExit:false와 수동·투자논리 청산은 승격하지 않으며 조회 자체는 revision·현금·저장 원문을 바꾸지 않는다. 절반 위험 청산은 이미 승인된 전량 투자논리 청산을 별도 주문으로 보존하고 위험 수량만 처리한다.

런타임 모델 입력은 최대480,000 UTF-8 바이트다. 원본 가격 이력과 이전 사이클의 주간 보고용 strategySnapshot은 전체 해시와 건수/시각으로 참조하며, 현재 research·investmentProcess·기술/위험 값·체결 결과는 유지한다. 주간 보고용 아카이브를 다시 붙여 같은 근거를 중복 전달하지 않는다. 입력이 그래도 한도를 넘으면 자료를 임의로 잘라 승인하지 않고 보류한다. 확대된 원본 요청의 서버/CLI 전송 한도는 UTF-8 10MB이며 모델 입력 한도와 구분한다.

## Cloud orchestration contract

Use this checkout's `web/run_autonomy.py` against the public Cloudflare proxy URL and verify the Mac app's `/api/context` advertises `logicReview.cloudConfigured:true`. During execution keep credentials exclusively in process memory, headers or hidden stdin; the operator-managed `.dev.vars` above is the Mac's configuration storage. Use actual source reading, existing US JEV discovery/admission `useJev:true` with the original complete candidates, and then the current updater. Collection includes all theme candidates, holdings and approved orders. It finishes before the shared review clock starts.

`web/run_autonomy.py` first performs risk-only processing. It queues exact collected evidence using server-generated account context. GitHub reviews a480,000-byte bounded, whole-evidence-hash summary. Runtime proof TTL remains15 minutes; the original window remains30 minutes, clipped to the current market phase, with five rounds shared by stock/ETF requests. The five-round limit is for the entire cloud window, not each scope: ETF, stock, repairs and revision-conflict reviews all consume it. Duplicate identical initial requests reuse the existing job without consuming a round. The queue's session ledger prevents a restarted updater from resetting an unexpired window. After expiry, a fresh invocation in the same market/date/phase may open a new window only when its review start and every collected price timestamp are at or after the previous deadline. It must omit the old window/job IDs. The new window has a new ID and its own five-round budget; old evidence and proofs cannot be reused. This permits an awaitingOpen open-phase retry with newly collected regular-session opening prices, while filled orders remain protected by session/order deduplication. The paused Mac compatibility path retains its existing per-scope five-round loop; it is not the approved cloud scheduling path.

For verified cloud **preopen** jobs, collection evidence expires with the original `reviewStartedAt`/`reviewDeadline` window, not 30 minutes after each `fetchedAt`. Each collected timestamp must be no later than the fixed review start and at most 30 minutes old at that start. Collection duration has no model-review limit, but evidence already stale at review start is held; the review does not renew expired prices. Quote/session/source, FX, financial, research and risk checks still use their existing bounds. Preopen cannot execute orders. Open/close submissions and unreviewed risk requests retain the original fetchedAt freshness check (30 minutes), and actual executions require the newly collected session prices with existing FX and risk checks. For cloud open/close, the updater clips the shared deadline to the earliest of review start+30 minutes, phase end, stock fetchedAt+30 minutes and every ETF fetchedAt+30 minutes. The queue rejects a deadline beyond its scope's oldest price expiry before fixing the session ledger or dispatching. GitHub delay and both reviews must finish before this announced deadline. A stale execution collection holds with `priceEvidenceStale`; it cannot be repaired by relabeling or refreshing timestamps. It must wait for the original window to expire, then obtain a valid fresh collection and review in the same phase or a later session. Cloud stock risk is submitted immediately after price collection, before financial/ETF collection and either review; its saved result is reused after the ETF review. The early cloud stock risk pass saves the collected universe. Research preflight then reads that saved universe without resubmitting old prices; the final server submission still validates the full candidate and all deterministic checks.

On `logicReviewHeld`, inspect `logicReview.issues`, `jobId`, `scope` and `reviewWindow`. Read missing original sources. To retry, call the same updater with `{site_url,token,reviewJobId:jobId,research:<repaired research>}` or `allocationDecision` for an ETF request. The retry retrieves the original collection from the authenticated queue and skips risk resubmission of those old prices; do not recollect prices, change phase or reset the clock. This retry does not claim a new risk-monitoring pass (`riskMonitoringVerified:false`); initial risk results remain saved. Continue normal scheduled risk monitoring with fresh prices. The server rejects any change outside research/decision/revision. Final POST409 returns a structured `logicReviewHeld` with `logicReview:{approved:false,reason:"revisionChanged",jobId,scope}`. Retry with `reviewJobId:jobId` (without the proof); the updater supplies the latest revision and `previousJobId` to the queue within the original window. Final POST400 similarly holds with `priceEvidenceStale` or `submissionInvalid`. Read the reported issue and repair only reasoning when possible, then retry by job ID. Approved-but-unsubmitted jobs and dispatch/runner error jobs with stored evidence are available for this retry, within the same deadline and shared five-round limit. If evidence storage failed, the job-ID retrieval holds because no candidate can be recovered; a caller retaining the exact original collection may enqueue supplemented research/decision with previousJobId, and the server still enforces the stored immutable digest. An unchanged candidate returns `reviewCandidateUnchanged`, so a failed submission never replays the old proof. After five rounds, expiry, missing evidence or phase change, report held/watch with the actual reason.

Cloud queue review requires explicit `market` and `phase`; the marketless four-hour compatibility mode is unsupported and returns `sessionPhaseRequired` without dispatch. The Mac compatibility loop is unchanged.

Times remain Asia weekdays08:00/09:20/16:00 Asia/Seoul and US weekdays08:30/09:50/16:30 America/New_York, including DST and Friday US close on Seoul Saturday. New activity is simulated regular-session investment only, never real brokerage orders. JEV remains US discovery/admission shadow review, not a logical approval or a profit probability.

Raw queue evidence is cleared on access after expiry and during the next enqueue. Rows are pruned after24 hours during enqueue. If no authenticated request arrives, D1 may retain expired private evidence until the next request; this cleanup is demand-driven. Logs contain IDs/states and credential-free error codes, never model replies, account snapshots or proofs.

The exact candidate/context JSON is split into500,000 UTF-16-unit chunks, without splitting surrogate pairs. Each D1 evidence row stays below1.5MB UTF-8, under the platform's2MB row limit. Metadata and proofs stay in separate small rows. The full canonical request hash is checked after reassembly, so full-candidate collections are never truncated to fit storage. Authentication/quota failures return `claudeAuthenticationUnavailable`/`claudeUsageLimit` rather than an ambiguous generic hold.

## Implementation decisions and approval boundary

The approved spec files retain their original requirements. This operating document records implementation decisions separately, and is not an amendment to those requirements. The user authorized implementation and authentication setup. Prices must be fresh within the existing30-minute limit at review start; this rejects expired evidence before opening a review window. Actual fills retain fetchedAt freshness. Cloud activation stays disabled pending genuine authentication and read-only proof verification. Mac schedules remain paused.

The decisions are: preopen cloud evidence uses the fixed review start/deadline; open/close keeps fetchedAt freshness and advertises the shorter shared deadline above; cloud five-round counting spans scopes and revision retries; marketless four-hour cloud requests hold with sessionPhaseRequired; final409/400 retries retain the original evidence and window. These describe current behavior, not permission to weaken price, financial, risk or logical-review checks. Saved external observations in claude-schedule-verification.md remain unchanged.

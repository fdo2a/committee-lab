# Multi-Asset Portfolio

KOSPI200·S&P500·닛케이225 내 후보 928개와 선택한 실제 관찰 종목을 대상으로 일곱 부서의 조사, 위험 심사, 자율 페이퍼트레이딩, 복기를 기록합니다. 실제 증권 계좌나 자금에 연결하지 않습니다.

## 아이디어 후보 검증과 최종 선정 (파이프라인 5, 2026-10-06)

산업·테마분석부와 마켓부가 출처 있는 투자 아이디어와 바스켓 후보를 발굴합니다. 펀더멘탈부와 별도 기술적 분석부가 같은 후보를 각각 검증하고, 퀀트리서치부가 실제 재무·가격으로 후보별 점수·순위·위험값을 계산합니다. 운용부가 기업·계량·기술 검토와 반대 의견을 종합해 종목·비중·전략을 결정합니다. 리스크관리부 심사 후 장전 리서치로 승인한 주문을 해당 거래일 정규장 시가로 개장 실행에서 모의 편입합니다.

산업·테마분석부의 내부 키는 호환을 위해 `screening`을 유지합니다. 기업 검토는 사업·공시와 숫자를, 기술 검토는 추세·모멘텀·변동성과 진입 시점을 확인합니다. 기술 의견의 `watch/avoid`는 운용 판단에 남기되 서버 진입 신호를 대체하지 않습니다. 사업 검증 실패·숫자 실패·출처 누락은 신규 편입을 막습니다.

최종·예비·제외 종목은 원본 컨셉 후보에서만 고르며 제외 이유를 기록합니다. 편입 없이 관찰할 때도 근거 있는 운용 판단을 남깁니다. 승인 후 컨셉 철회·검토 제거·36시간 이상 지난 조사·선정 변경이 확인되면 진입을 만료시킵니다. 기존 계좌·유닛 위험 청산과 세션 중복 방지는 유지합니다. 과거 v4 조사와 주문은 새 절차의 통과 결과로 간주하지 않습니다.

최초 의견과 수정 이유는 아이디어·종목별로 보존합니다. UI는 컨셉, 후보별 기업·기술 검토, 최종 바스켓과 위험 심사를 연결하고 조사 준비 시점과 실제 실행 기록을 나눠 표시합니다. 별도 모델 에이전트를 추가로 자동 실행하는 구조는 아닙니다.

## 부서 책임과 계량 선정 (2026-10-06)

퀀트리서치부를 별도로 둡니다. 기업 검증은 펀더멘탈부, 어떤 후보를 먼저 살지 정하는 순위와 위험 계산은 퀀트부(매수 거부권 없음), 진입 시점은 기술적 분석부, 최종 바스켓·비중·목표·손절·기한은 운용부, 독립 한도 심사는 리스크관리부가 맡습니다. 새 모델·유료 API·외부 퀀트 입력은 요구하지 않습니다. [부서별 역할과 프로젝트 점검](docs/trend-unit-departments.md)에 입력·산출물·권한·제안서 대비 차이를 기록했습니다.

`analysis.quantResearch`는 아이디어별 최대100개 조사 후보의 가치·ROE·매출성장·방향별 가격모멘텀과 Fama-French 3팩터 알파를 동등가중해 순위를 기록합니다(알파가 없으면 4요소 각 25%). 3팩터는 Kenneth French Data Library의 공개 일별 팩터(미국·일본)를 가격 수집 때 함께 받아, 종목별 최근 252거래일(최소 120일) 초과수익을 시장·규모(SMB)·가치(HML)에 회귀합니다. 알파 t값을 점수로 바꾸고(t=+2.5 → 100, 0 → 50, 숏은 반전) 시장·규모·가치 베타와 R²를 `ff3`로 함께 기록합니다. 한국 종목은 자체 팩터가 없어 FF3 알파 없이 필수 4요소로 계산합니다(2026-10-27 사용자 결정). 팩터는 1~2개월 늦게 공개되고 일본 팩터는 달러 수익률이라 환율 효과가 섞이며, 알파는 과거 초과수익일 뿐입니다. 필수 4개 팩터·서버 숫자 통과·재무 수집 30일 미만이 필요하며 상위30개를 압축 후보로 표시하고 선정·예비·제외·관찰 이유를 연결합니다. 연간 재무는 주 1회 재조회하며 수집 후 24시간이 지났다는 이유만으로 보류하지 않습니다. 규모·배당·이익전망 수정치는 미수집으로 표시합니다. 편입 계획·승인·체결에서 현재 자료를 재검사합니다. `portfolioUnitRisk`는 공통 관측구간60개 이상의 유닛 간 상관·중복·자료 누락을, `unitPerformance`는 종료 유닛별 수익 성공률·목표 도달률·평균 수익/손실·소요기간을 제공합니다. 최신 근거 있는 원본 컨셉 철회도 기존 유닛 청산 계획으로 연결합니다.

## 데이터와 한계

`web/collect_prices.py`가 Python에서 finance.yahoo.com의 일봉·최근 정규장 가격 및 USD/KRW·JPY/KRW를 수집합니다. 네이버증권 https://stock.naver.com/ 및 Yahoo Finance Japan https://finance.yahoo.co.jp/는 시장 조사·교차 확인 자료입니다. 자동 수집에 실패하면 가격을 생성해 대체하지 않습니다.

`GET /api/research-data`는 서버의 DART_API_KEY, EDINET_API_KEY, FRED_API_KEY를 사용합니다. DART는 최근 7일 첫 100건 공시, EDINET은 최근 7일 중 최신 제출일 목록 최대 300건, FRED는 DGS10·FEDFUNDS·CPIAUCSL·UNRATE를 조회합니다. 공시 목록은 원문 재무 검증을 대체하지 않습니다. 각 제공기관 오류와 자료 범위를 명시합니다. 원문·기업 IR·SEC·신뢰할 수 있는 뉴스는 클라우드 조사에서 추가 확인합니다.

미국 SEC 공시 수집은 `POST /api/us-research` 또는 MCP `collect_us_research`로 요청합니다. 입력 예시는 `{ "symbols": ["AAPL"], "query": "Cash flow and earnings risks", "useJev": true }`입니다. 미국 등록 종목만 한 번에 1~5개, 영문 질문은 1~500자입니다. 서버 비밀 설정에 `SEC_USER_AGENT`(서비스 이름과 실제 연락처 이메일), `TYPESAFE_API_KEY`를 등록합니다. 키와 연락처는 JEV 판단 입력이나 반환 자료에 포함하지 않습니다. `useJev` 기본 false이며 기존 수집·자동화에서 유료 호출을 자동으로 켜지 않습니다.

SEC 최신 제출 목록의 첫30건과 그 목록에 있는 최신 10-K·10-Q·20-F·40-F 및 각 수정본을 보존합니다. JEV는 `jev-1.13.0`에 영문 메타데이터만 보내 읽기 순서를 정하고 모든 후보를 반환합니다. 최신 정기 보고서와 수집 범위 내 8-K·6-K 및 수정본은 필수로 표시합니다. confidence 0.8 미만은 `uncertain`이며, 0.8은 실제 금융 자료에서 검증하지 않은 초기 기준입니다. confidence는 주가 상승 확률이 아닙니다. SEC 오류 시 성공한 종목을 보존하고 JEV를 호출하지 않으며, JEV 오류·잘못된 응답은 후보 목록을 보존합니다. 유료 호출은 자동 재시도하지 않습니다. 원문·첨부·과거 분할 제출 목록·기업 IR·뉴스는 이 수집 범위에 포함하지 않습니다.

미국 종목 선정의 두 단계 비교 실험은 [JEV 후보 평가](docs/jev-pilot.md)를 따릅니다. 후보 발굴 직후와 독립적인 최종 선정 직후에 `POST /api/jev-evaluate` 또는 MCP `evaluate_us_candidates`를 명시적으로 호출합니다. `JEV_PILOT_ENABLED=true`는 context에 활성화 지침을 알리고, 실제 유료 호출은 여전히 `useJev:true`가 필요합니다. JEV 결과로 기존 종목·비중·승인·체결을 변경하지 않습니다. `/api/jev-evaluations`와 MCP `get_jev_evaluations`는 최근20개 기록을 반환합니다. 정기 미국 장전에서는 조사 주체가 `jev-packet.json`을 쓰고 호스트(`scripts/research-agent.mjs`)가 두 단계를 `replay:true`로 요청합니다. 평가 기록은 metadata만 갱신하므로 이후 운용 요청은 최신 context의 revision을 사용해야 합니다.

초기 관찰 종목은 각국12개, 총36개이며 updater는 저장·제출한 모든 테마 후보를 자동 합산해 가격 수집 범위를 확장합니다. 기존 관찰·보유·승인 주문 종목은 보존합니다. 전체 시장 스크리닝이 아니며, 60개 전략도 유사한 조합을 포함합니다. 과거 검증에는 현재 구성 종목·개정 데이터·60개 전략의 평가 구간 재사용에 따른 선택 편향의 한계가 있습니다. 비용은 편도 수수료 0.015%, 슬리피지 0.1% 가정이며 배당·환전 비용·일본 100주 단위는 미반영합니다. 장전·개장·마감 관측은 장중 가격 움직임을 놓칠 수 있습니다. 손절·논리 훼손 판단은 이후 시가 청산을 예약하며 장중 즉시 체결을 보장하지 않습니다.

## 저장 및 보안

D1 DB의 단일 공유 서버 계좌에 기록을 저장합니다. D1은 문자열·행을 2MB로 제한하므로 1MB를 넘는 계좌 상태는 `paper_account_part`에 조각으로 저장하고 `paper_account.state`에는 포인터만 둡니다. `POST /api/import`는 빈 데이터베이스에만 내보낸 장부를 넣는 이전 전용 경로이며 기존 계좌는 교체하지 않습니다(`scripts/import-ledger.mjs`). revision 비교와 시장별 거래일·단계 식별자로 중복 체결·덮어쓰기를 방지합니다. 첫 실제 가격 전환 시 이전 시연 계좌를 별도 행에 보관하고 새 모의 계좌를 시작합니다. 과거 브라우저 계좌는 자동 삭제하지 않습니다.

Cloudflare 배포에서는 Worker가 모든 요청(정적 파일 포함)의 `Cf-Access-Jwt-Assertion`을 `worker/auth.mjs`로 직접 검증합니다. `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `OWNER_EMAIL`, `ACCESS_SERVICE_ID` 중 하나라도 없으면 전부 거부합니다. 소유자 이메일 JWT만 `/api/action`, `/api/pause`, `/api/schedule`, MCP 도구 호출을 할 수 있고, 등록된 서비스 토큰(`common_name`)은 `worker/index.mjs`의 `SERVICE_ROUTES`(import·context·session·account·runs·run·attempt·research·research-check·research-data·us-research·jev-evaluate·jev-evaluations·universe·allocation·market-reports·weekly-report-context·weekly-reports)와 `/api/logic-review*`, 정적 파일만 사용할 수 있고 그 밖의 API(action·watchlist·providers 등)는 403입니다. 서비스의 `/api/us-research`는 `useJev:false`만 허용합니다. 클라이언트는 `CF-Access-Client-Id`/`CF-Access-Client-Secret`을 보내며 `https://` origin만 허용합니다. 앱은 무료 플랜의 요청당 CPU 10ms를 넘기 때문에 운영자 Mac에서 실행하고, `portfolio` Worker는 Access 뒤에서 요청을 Workers VPC 터널로 넘기는 프록시(`proxy/`)만 맡습니다([Mac 실행 안내](docs/mac-runner.md)). 배포는 `npm run deploy`(승인 빌드로 Mac용 `dist/` 생성 후 `proxy/wrangler.toml` 배포)이며, 루트 `wrangler.toml`은 Mac 로컬 실행과 D1 설정 전용이라 `portfolio`로 배포하지 않습니다. 이전 절차는 [Cloudflare 이전 계획](docs/cloudflare-migration-plan-2026-10-17.md)에 있습니다.

기존 ChatGPT Sites 배포는 `AUTH_PROVIDER=sites`를 설정한 경우에만 Sites의 private dispatch 경계와 `oai-authenticated-user-id` 헤더를 신뢰합니다. 이 값은 Cloudflare에 설정하지 않습니다. 두 호스트를 동시에 운용하지 않으며 이전 후 Sites 계좌는 일시정지 상태로 둡니다.

Mac 앱의 API 키와 Access·검토 설정은 저장소 밖 `~/committee-runner/.dev.vars`(운영자 본인 소유 일반 파일, 권한 `0600`)에 직접 입력하고 Mac 서버를 재시작합니다. 프록시 Worker나 루트 설정의 `wrangler secret put`으로 등록하면 Mac 앱이 읽지 못합니다. 클라우드 검토에는 `CLOUD_REVIEW_ENABLED`, `CLOUD_REVIEW_REPOSITORY`, `CLOUD_REVIEW_REF`, `CLOUD_REVIEW_DISPATCH_TOKEN`, `CLOUD_REVIEW_PUBLIC_KEY`가 필요합니다. `scripts/setup-cloud-auth.py`는 GitHub 접근을 확인하고 구독 OAuth만 GitHub repository secret으로 등록하며, dispatch 토큰은 저장하지 않고 수동 입력을 안내합니다. 전체 변수·권한 확인 절차는 [클라우드 검토 설정](docs/cloud-review-setup.md)을 따릅니다. 실제 구독 인증과 읽기 전용 증명 검증 전에는 `CLOUD_REVIEW_ENABLED=false`, Mac 예약은 중지 상태로 유지합니다. 브라우저 번들·계좌 데이터·로그·자동화 프롬프트에 키를 넣지 않습니다.

## 예약 실행 (GitHub Actions)

이 워크플로는 **비공개 저장소에서만** 사용합니다. 계좌 결과가 Actions 로그와 작업 요약에 남으므로, 작업 전체를 `github.event.repository.private == true`로 제한합니다. 공개 저장소에서는 예약·수동 실행 모두 건너뜁니다. 공개 저장소 `fdo2a/committee`에는 계좌·인증 자료를 업로드하지 않습니다.

`.github/workflows/scheduled-operation.yml`이 아시아 08:00/09:20/16:05 KST, 미국 08:30/09:50/16:30 뉴욕 시각에 체크아웃의 `web/run_autonomy.py`를 Cloudflare 배포에 대해 실행합니다. 실행 전 체크아웃 `sourceDigest()`와 배포 `codeDigest`가 같아야 하며 다르면 거부합니다. 저장소 변수 `COMMITTEE_SITE_ORIGIN`, secrets `COMMITTEE_ACCESS_CLIENT_ID`/`COMMITTEE_ACCESS_CLIENT_SECRET`가 필요합니다. 장전 실행은 50분 일찍(07:10 KST, 07:40 뉴욕) 시작해 `scripts/research-agent.mjs`가 Claude(Sonnet 5.5, 구독)로 최대 40분 안에 조사 JSON을 작성합니다. 예약이 지연되면 조사 시간만 줄여 개장 45분 전(08:15 KST, 08:45 뉴욕)에 끝내고, 10분 미만이 남으면 조사 없이 위험 전용으로 진행합니다. 저녁 조사(평일 전날 18:05 KST, 22:05 뉴욕)는 세션 없이 조사만 해서 `research.json`을 초안 아티팩트로 남기고, 다음 장전 조사가 16시간 이내의 같은 브랜치 초안을 이어받아 매크로·가격·뉴스를 그날 원문으로 갱신합니다. 초안이 없거나 오래되면 처음부터 조사합니다. 저녁 시각은 다른 실행의 Claude 사용과 겹치지 않게 골랐습니다. GitHub 예약 지연에 대비해 아시아 개장·마감 실행은 예정 시각보다 약 1시간 늦게 시작해도 받아들입니다. 미국 개장·마감 실행은 뉴욕 시각 09:40 이상 10:15 미만, 16:20 이상 16:55 미만에서만 받아들입니다. 조사 주체는 별도 Docker 컨테이너에서 서버 context·universe·research-data·market-reports 파일과 공개 웹 원문을 읽습니다. 서비스 자격 증명은 단계별 호스트 프로세스에만 주고 모델에는 조사 폴더와 구독 OAuth만 전달하며, `/api/research-check`의 누락을 최대 3라운드 보완한 뒤 updater가 수집·클라우드 검토·제출을 이어갑니다. 조사가 없거나 부분이면 그대로 기록되고 위험 전용으로 진행합니다. 종료코드 2는 보류, 1은 실패입니다. 아래 ChatGPT Sites 절차는 이전 호스트용 기록입니다.

## 클라우드 실행 절차

1. 매 실행에서 Sites get_site로 동일 Site를 열고 owner-private 상태와 연결된 자동화를 확인합니다. service access token은 이 Site origin의 요청 헤더에만 사용하며 출력·저장하지 않습니다.
2. GET /api/context를 읽습니다. paused이면 변경하지 않고 중단합니다. 시장별 실행은 `/api/session`의 실제 거래일·단계와 sessionRuns를 확인합니다. 시장 없는 호환 실행만 한국 시간 4시간 슬롯의 lastSlot을 확인합니다.
3. 클라우드 활성화 전에는 기존 위험 점검·청산만 수행합니다. 실제 Claude 구독 인증·읽기 전용 증명 검증과 기존 시장별 예약 지시문 확인을 마친 뒤에만 클라우드를 활성화합니다. `logicReview.cloudConfigured:true`이면 승인된 [Claude 구독+JEV 설계](docs/superpowers/specs/2026-10-10-cloud-investment-design.md)에 따라 출처 있는 research·allocationDecision을 준비하고 비공개 GitHub 검토 대기열을 사용합니다. Mac 예약과 과거4시간 예약은 중지 상태를 유지합니다.
4. 동일 Site에서 GET /collect_prices.py, /collect_fundamentals.py, /run_autonomy.py, /logic_review.py, /index-catalog.mjs, /etf-catalog.mjs를 읽어 같은 임시 디렉터리에 가져옵니다. run_autonomy.py를 JSON stdin {site_url,token,market,phase}로 실행합니다. 시장·단계는 /api/session으로 확인하며 시장 없는 기존4시간 모드는 Mac 검토 호환용입니다. 클라우드 검토는 market·phase가 있는 세션 모드만 지원하며 누락 시 `sessionPhaseRequired`로 보류합니다. 가격·연간 재무 수집과 POST /api/run, GET /api/context readback을 완료하는 자체 updater입니다. `cloudConfigured:true`이면 서버 대기열을 사용하고, 미설정 클라우드는 위험 전용 제출 후 macReviewerRequired로 신규 활동을 보류합니다. 가격·재무·ETF 수집 완료 뒤 updater가 최대30분의 reviewWindow를 만들며 동일 실행 재호출에는 반환된 reviewWindow를 그대로 전달합니다. 수집 시간은 검토 시간에 포함하지 않습니다. 누락·오류 시 기존 위험 청산은 수행하고 신규 검토만 보류합니다. 클라우드는 검토 창 전체에서 ETF·주식·revision 충돌 재심사를 합산해 최대5회입니다. 409·400 보류는 jobId와 scope를 확인하고 `reviewJobId`로 원본 증거를 조회하여 같은 창에서 재심사합니다. 세부 계약은 [클라우드 검토 설정](docs/cloud-review-setup.md)을 따릅니다. 정상 반복 실행은 새 배포가 필요 없습니다.
5. 결과만 한국어로 보고합니다: 체결·총자산·손익·위험 조정·자료 오류. 확인되지 않은 원인을 학습 성과로 주장하지 않습니다. 실패 시 저장 전환 없이 명확한 오류를 보고합니다.

활성화 후 클라우드 조사 주체는 GET /api/research-data와 공시·기업 IR·거시·산업·뉴스 원문으로 컨셉과 후보군을 조사하고, 기업·기술 검토와 운용 판단을 연결한 뒤 Claude의 논리 검토를 받습니다. 출처·조회 시점·미확인 범위를 기록하고 미확인 자료를 만들지 않습니다.

조사 주체가 제출하는 JSON의 기존 요약·sources는 유지하며 `investmentIdeas`, `departmentResearch.{fundamental,technical}`, `macroScorecard`, `trendUnits`를 제출합니다. 정확한 필드와 한도는 `/api/context` 및 [v5 설계](docs/superpowers/specs/2026-10-05-idea-led-investment-design.md)에 있습니다. 아이디어 최대 12개, 후보 1~30개와 기업·기술 검토의 복합 키 `(ideaId,symbol)`, 등록된 HTTPS 출처가 필요합니다. 두 부서는 전체 관찰 종목이 아닌 발굴 후보를 검증합니다.

최종 유닛은 원본 `ideaId`, 구성 2~20개·비중 합계100%, 예비 최대10개, 제외 이유를 기록합니다. 검토 후 편입 없으면 아이디어에 `managementReview:{status:'watch',reason,sourceUrls:[]}`를 남깁니다. 제출 `businessPass:true`는 서버 숫자 검사 `numericPass`를 대체하지 않습니다. 동일 종목의 다른 아이디어 검토도 통과를 대신하지 않습니다. 기존 screening 입력은 과거 조회·청산 호환에만 사용하며 신규 진입을 허가하지 않습니다.

## 개발

Node.js 22 이상. `npm install`, `npm test`, `npm run build`. D1 스키마는 db/schema.ts, 이력은 drizzle/입니다. `npm start`는 정적 UI만 제공하며 서버 계좌 API는 배포 Site에서 사용합니다.

코드 변경 후에는 `npm run review:code`로 테스트·Claude 논리 검토·Codex 보완·재검토·승인 빌드를 실행합니다. `npm run build`는 정확한 최신 소스에 대한 유효한 Claude 승인을 요구합니다. 예약 주식·ETF 신규 투자는 선택된 Claude 검토 경로의 서명 승인이 필요하며 기존 위험 청산은 계속 진행합니다. 설치·승인 범위·실패·재시도는 [Claude 논리 검토 운영](docs/claude-logic-review.md)을 따릅니다.

## 선택 기능: MCP 조회

MCP는 기존 API·Python 수집·운용에 필수가 아닙니다. 대화에서 AI가 필요한 투자 자료를 직접 조회할 때 사용하는 선택 기능입니다. 구현과 연결 방법은 [MCP 안내](docs/mcp.md)에 기록했습니다. 배포 여부와 관계없이 기존 수집·4시간 슬롯·위험 심사를 대체하지 않습니다.

## 자동 운용 판정과 복기

재무는 수집 30일(연간 재무는 주 1회 재조회, 2026-10-28 사용자 요청으로 24시간에서 완화)·연간 기간 550일 이내, 회사 통화 일치, 동일 연간 필수 계정, 흑자·매출 감소 15% 이내·연간 EPS PER은 기본 60배 이하이며, 매출 성장률 15% 이상·ROE 10% 이상·영업현금흐름 양수인 기업에 한해 80배 이하를 허용합니다. 다른 재무 기준은 동일하게 적용합니다. 비금융업은 영업현금흐름 양수·차입금/자기자본 4배 이하이고, Yahoo가 차입금을 제공하지 않으면 흑자·영업현금흐름 양수 조건으로 대신합니다. 금융업은 ROE 5% 이상입니다. (2026-10-25 사용자 요청으로 PER 45/60배·차입금 3배에서 완화) Yahoo 집계이므로 공시 원문과 최신 분기를 조사자가 별도로 검토하고 질적 통과 여부를 제출해야 합니다. 점수나 AI의 승인 문장만으로 재무 수치를 대체할 수 없습니다.

실제 가격 모드는 앞 `max(220,floor(거래일 수×70%))` 거래일을 훈련하고 이후 구간을 검증합니다. v5 신규 편입은 해당 Trend Unit의 최종 구성종목만 검증하며, 구성종목 수가 n이면 훈련 청산 최소 `max(3,n)`건·검증 청산 최소 `max(2,ceil(n/2))`건, 두 구간 평균 수익 양수와 검증 개별 최대낙폭15% 이하를 요구합니다. 전체 관찰종목 비교 연구의 훈련24건·검증0.5n건 조건은 해당 바스켓의 선행 조건으로 사용하지 않습니다. 소수 바스켓은 표본이 적고 현재 구성·평가 구간 성과로 조합을 고르므로 완전 독립 검증이 아니며 이후 모의운용이 추가 검증입니다. 전체 최근 청산3회 연속 손실 시 규모50%, 전략별3회 연속 손실 시 신규 중단·5회 이상 합산 손실 시 절반으로 제한합니다. 범용 모델 재훈련이 아니라 설명 가능한 규칙 조정입니다.

GET /api/runs에서 최근 20개 슬롯의 진행·실패·완료와 부서 보고서를 읽습니다. 계좌 저장 후 로그 실패 시 같은 슬롯 재시도로 로그를 복구합니다. 같은 슬롯을 재시도해도 새 거래가 발생하지 않습니다. 일시정지 버튼은 다음 서비스 실행과 모든 신규 자동 거래를 중단합니다. 구독 한도가 없으면 자동 작업은 유료 API나 크레딧 구매로 전환하지 않습니다.

## 롱·숏 통합 모의계좌 (파이프라인 2)

하나의 계좌에서 서로 다른 종목의 롱과 숏을 함께 보유합니다. 기존 60개 조합 중 하락 20개는 SH21–SH40 숏 헤지 전략으로 바뀌었고 별도 ID로 복기합니다. 부서별 후보 중 사업·재무 검증을 통과한 기업의 국가별 하락 추세를 헤지하며, 기업 검증 실패나 자료 누락을 숏 근거로 사용하지 않습니다. 동일 종목 양방향 진입은 보류합니다.

순자산 = 현금 + 롱 평가금액 − 숏 상환 의무. 숏 매도대금 또는 현재 상환 의무 중 큰 금액과 숏 평가금액 100% 추가 증거금을 가용 현금에서 제외합니다. 연 3% 대차료를 경과 시간에 비례해 차감합니다. 총노출 100%, 숏 총노출 30%, 절대 순노출 80%, 롱 종목 20%, 숏 종목 10%, 업종 총노출 40%, 계획 손실 0.8%, 합산 손절 손실 5%, 최대낙폭 10% 제한입니다. 승인된 진입 주문도 한도를 예약합니다. 증거금 부족은 새로 관측된 가격에서 숏 상환하며 극단적 갭으로 순자산이 소진되면 음수 손실을 그대로 기록하고 신규 진입을 중단합니다.

이는 대차 가능한 것으로 가정한 연구 모델입니다. 실제 대차 재고·변동 대차료·국가별 규제·배당 보전·리콜·브로커 증거금은 재현하지 않습니다. Yahoo 가격만으로 실제 공매도 가능 여부를 알 수 없습니다. 시장별 cloud updater가 새 Python/Worker 코드를 사용하며 별도 유료 API를 추가하지 않습니다.

DART 요청은 프로그램을 명시하는 User-Agent를 사용합니다. 생산 서버에서 이 헤더가 없는 요청은 오류 페이지로 302 이동했지만 헤더를 넣으면 정상 코드 000을 받았습니다. 인증키를 가진 제공기관 요청은 리다이렉트를 따라가지 않아 키가 다른 경로로 전달되지 않습니다.

### 트렌드 유닛 투자 프로세스 (v4)
산업·시장 컨셉 후보를 기업·기술 검증 후 운용부가 최종 바스켓으로 선정하고 리스크관리부가 심사합니다. 구성 종목 국가별 거시 근거·참조지수·투자 논리·철회 조건·사전 위험 예산이 없는 신규 편입은 보류합니다. 한 아이디어·바스켓은 여러 나라 종목을 섞을 수 있습니다(2026-10-29 사용자 지시). 첫 체결부터 최대 3개월 기한, 유닛 손실 한도 절반의 1회 축소, 전체 한도·목표·기한 도달 시 청산을 관리합니다. 과거 제안서의 개별 종목·성과 수치는 적용하지 않습니다. 상세 방법과 구현 범위는 [투자 프로세스 분석](docs/trend-investment-process.md)에 기록했습니다.

허용 후보는 KOSPI200 200개, S&P500 503개 상장 주식 클래스, 닛케이225 225개입니다. 한국·미국은 공식 추종ETF 전체 주식 보유표의 대용치와 기준일을 표시하며 일본은 공식 지수 구성표를 사용합니다. 현재 36개 실제 가격·독립 조사만 활성화하며 전체928개를 모두 조사한 것으로 표시하지 않습니다.
